# Node log ingestion, parsing, and SNTP time sync design

## Context

Firmware already forwards every log line over MQTT: `main/src/infrastructure/logger/leveled/stdio_impl.c`'s `print_log` builds a raw string
`DD/MM/YYYY HH:MM:SS.mmm [LEVEL] [TAG] message` (max 512 bytes, no trailing
newline), which `application/internal/log_forwarding` fans out to
`messaging_callbacks/impl.c`'s `on_log_message` sink, which calls
`def_pub->log(...)` → `infrastructure/messaging/def_pub/mqtt_impl.c`'s
`log_impl`, publishing the raw bytes (no JSON wrapping) to
`/pub/{device_id}/log`.

On the backend, this is already fully wired end-to-end — subscribed at
registration/resubscribe, dispatched by
`internal/presentation/mqtt/event/message.go`'s `OnMessage` to
`internal/presentation/mqtt/handler/log.go`, which calls
`MessagingCallback.Log(ctx, NodeLogMessageRequest{DeviceId, Payload})` — but
`internal/application/node/messaging_callback/usecase.go`'s `Log()` is a
no-op stub. This plan implements it.

Confirmed device-side facts that shape the design:
- 5 log levels only: `NONE`, `ERROR`, `WARN`, `INFO`, `DEBUG` (`domain/models/logger.h`'s `DOMAIN_MODELS_LOGGER_LEVEL` X-macro) — no `VERBOSE`.
- The embedded timestamp is `localtime_r`-derived, and the firmware never calls `setenv("TZ", ...)` anywhere — ESP-IDF defaults to UTC when no TZ is set, so the embedded timestamp is genuinely UTC today, made *reliable* (rather than just defaulting to the epoch or drifting) by this plan's SNTP addition.
- No AP mode exists in this firmware (STA-only) — the original ask's "after ap and sta" doesn't apply; there's only STA to sequence after.
- TimescaleDB is already a hard dependency (`create_hypertable` used by `telemetry_records`/`action_logs`), but no compression policy exists yet anywhere in this codebase — this plan introduces the first one.

Decisions confirmed with the user before writing this plan:
- Malformed log lines get a best-effort fallback (never dropped): `level=NONE`, `tag=""`, `message=<entire raw string>`, `logged_at=<server receive time, UTC>`.
- Only the 4 parsed fields are stored — no redundant raw-line column.
- "1 week compression" means an Timescale compression *policy* (`add_compression_policy(..., INTERVAL '1 week')`), not a 1-week chunk interval — chunking stays at the existing 7-day convention, which incidentally is the same duration, but the two are different mechanisms and this plan adds the policy on top of the existing chunking convention.
- SNTP sync is non-blocking: initialized once at startup, kicked off (or restarted) on every `STA_GOT_IP` event, never blocking boot or the event handler.
- A retrieval HTTP endpoint is in scope, mirroring `telemetry_record`'s `ReadByFilter`/`DeleteByFilter` + flat-route pattern exactly.

## 1. Migration: `node_logs` hypertable

New enum `node_log_level` (`'NONE','ERROR','WARN','INFO','DEBUG'`). New
table `node_logs`, following the `telemetry_records`/`action_logs` template:

```sql
CREATE TYPE node_log_level AS ENUM ('NONE', 'ERROR', 'WARN', 'INFO', 'DEBUG');

CREATE TABLE node_logs (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY,
    node_device_id TEXT NOT NULL REFERENCES nodes (device_id),
    level node_log_level NOT NULL DEFAULT 'NONE',
    tag TEXT NOT NULL DEFAULT '',
    message TEXT NOT NULL,
    logged_at TIMESTAMPTZ NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (id, logged_at)
);

SELECT create_hypertable('node_logs', 'logged_at', chunk_time_interval => INTERVAL '7 days', if_not_exists => TRUE);

CREATE INDEX idx_node_logs_node_device_id ON node_logs (node_device_id);
CREATE INDEX idx_node_logs_level ON node_logs (level);
CREATE INDEX idx_node_logs_logged_at_desc ON node_logs (logged_at DESC);
CREATE INDEX idx_node_logs_node_logged_at_desc ON node_logs (node_device_id, logged_at DESC);
CREATE INDEX idx_node_logs_level_logged_at_desc ON node_logs (level, logged_at DESC);

ALTER TABLE node_logs SET (
    timescaledb.compress,
    timescaledb.compress_segmentby = 'node_device_id',
    timescaledb.compress_orderby = 'logged_at DESC'
);

SELECT add_compression_policy('node_logs', INTERVAL '1 week');
```

`compress_segmentby = node_device_id` because "one node's logs over time" is
the dominant query shape (matches the `node_device_id` index precedent from
`telemetry_records`). Down migration: `SELECT remove_compression_policy('node_logs', if_exists => TRUE); DROP TABLE IF EXISTS node_logs; DROP TYPE IF EXISTS node_log_level;`
(policy must be removed before the table drop can proceed cleanly).

No audit columns (`created_by`/etc.) or soft-delete — append-only, matching
`telemetry_records`/`action_logs`, not the config-style tables.

## 2. Domain model + repository

- `internal/domain/models/node_log.go`: `NodeLog` struct
  (`Id int64`, `NodeDeviceId string`, `Level NodeLogLevel`, `Tag string`,
  `Message string`, `LoggedAt time.Time`, `CreatedAt time.Time`) plus
  `NodeLogLevel string` with 5 exported constants
  (`NodeLogLevelNone`, `NodeLogLevelError`, `NodeLogLevelWarn`,
  `NodeLogLevelInfo`, `NodeLogLevelDebug`).
- `internal/domain/contracts/repository/node_log.go`:
  ```go
  type NodeLog interface {
      Create(ctx context.Context, nodeDeviceId string, level domainmodels.NodeLogLevel, tag string, message string, loggedAt time.Time) (id int64, err error)
      ReadByFilter(ctx context.Context, request ReadNodeLogByFilterRequest) (logs []domainmodels.NodeLog, total int, err error)
      DeleteByFilter(ctx context.Context, request DeleteNodeLogByFilterRequest) (total int, err error)
  }
  ```
  Filter request structs carry pointer fields (`NodeDeviceId *string`,
  `Level *domainmodels.NodeLogLevel`, `LoggedAtStart/End *time.Time`,
  `Page`/`Limit int`), matching `telemetry_record`'s contract shape.
- `internal/infrastructure/repository/node_log/{postgres.go,postgres_query.go}`:
  `BasePostgres` embedding, squirrel query builders, package-level
  `nodeLogColumns`, errors via `QueryBuildError`/`MapPgxError`. A
  foreign-key violation on `node_device_id` (unknown device) is already
  handled by `MapPgxError`'s existing `23503`/`23505` case — no new error
  mapping needed.
- `internal/infrastructure/repository/shared/scan_pgx.go`: add
  `ScanPgxNodeLog(row pgx.Row)` / `ScanPgxNodeLogs(rows pgx.Rows)`.

## 3. Application-layer parsing (the ask's core requirement)

New file `internal/application/node/messaging_callback/log_parser.go`:
```go
var logLineRe = regexp.MustCompile(
    `^(\d{2})/(\d{2})/(\d{4}) (\d{2}):(\d{2}):(\d{2})\.(\d{3}) \[(\w+)\] \[([^\]]*)\] (.*)$`,
)

func parseLogLine(raw string) (level domainmodels.NodeLogLevel, tag string, message string, loggedAt time.Time) {
    match := logLineRe.FindStringSubmatch(raw)
    if match == nil {
        return domainmodels.NodeLogLevelNone, "", raw, time.Now().UTC()
    }
    day, month, year, hour, min, sec, ms := match[1..7] // parsed as ints
    parsedLevel, ok := parseLevel(match[8]) // match against the 5 known levels
    if !ok {
        parsedLevel = domainmodels.NodeLogLevelNone
    }
    loggedAt = time.Date(year, month, day, hour, min, sec, ms*1e6, time.UTC)
    return parsedLevel, match[9], match[10], loggedAt
}
```
(Exact Go code — int conversions, `parseLevel`'s switch, and named capture
group handling — is written out precisely in the implementation plan; this
spec fixes the *behavior*, not the literal syntax.)

`usecase.go`'s `Log()`:
```go
func (u *usecase) Log(ctx context.Context, request domainusecasesnode.NodeLogMessageRequest) error {
    const tag = "node/messaging_callback/Log"

    level, logTag, message, loggedAt := parseLogLine(string(request.Payload))

    if _, err := u.nodeLog.Create(ctx, request.DeviceId, level, logTag, message, loggedAt); err != nil {
        u.logger.Error(ctx, tag, "failed to store node log", domainmodels.LoggerMeta{
            "err":       err,
            "device_id": request.DeviceId,
        })
        return err
    }

    return nil
}
```
`nodeLog domaincontractsrepository.NodeLog` is added as a new constructor
param on `usecase`, wired through composition the same way `actionLog`
already is. No node-existence pre-check (matching `telemetry_record`'s
precedent of relying on the FK constraint rather than an extra read).

## 4. Retrieval endpoint

Mirrors `telemetry_record` exactly, as a top-level resource (not nested
under `/nodes/{id}`):
- `internal/domain/usecases/node_log/query.go`: `Query` interface
  (`ReadByFilter`, `DeleteByFilter`), same shape as
  `domainusecasestelemetry.Query`.
- `internal/application/node_log/query/usecase.go`: thin usecase wrapping
  the repository contract.
- `internal/presentation/http/handler/node_log/handler.go`:
  `NodeLogGetList` (`GET /v1/node-logs`, filters: `node_device_id`,
  `level`, `logged_at_start`, `logged_at_end`, pagination) and
  `NodeLogDelete` (`DELETE /v1/node-logs`, same filter shape), copying
  `presentationhttphandlertelemetry`'s handler structure and swagger
  annotation style verbatim.
- `internal/presentation/http/response/node_log.go`: `NodeLogResponse` +
  `NodeLogs([]domainmodels.NodeLog) []NodeLogResponse` collection mapper.
- Routes in `route.go`: `v1.GET("/node-logs", ...)` /
  `v1.DELETE("/node-logs", ...)`, permissions `node_log:get`/
  `node_log:remove` added to `permission.json` and granted to `super`/
  `admin` in `role.json` (learning directly from the dynamic-config
  sub-project's post-hoc discovery that a new permission is easy to add to
  `permission.json` and forget to grant in `role.json` — this plan grants
  both in the same task).

## 5. Firmware: SNTP

No AP mode exists — nothing to sequence after there; only STA netif
matters.

- `main/src/composition/main/infrastructure.c`: right after
  `inf_device_wifi_esp_impl_init(...)` (netif now exists), call
  `esp_netif_sntp_init(&config)` once, with
  `config = ESP_NETIF_SNTP_DEFAULT_CONFIG(NTP_SERVER)`, `NTP_SERVER`
  defined as a `#define` (`"pool.ntp.org"`) alongside the file's other
  `DEFAULT_*` constants — not a preloaded/configurable setting; this is
  infrastructure plumbing, not a per-device operational parameter like MQTT
  host/port.
- `main/src/.../wifi_manager/impl.c`'s existing
  `DOM_MODELS_WIFI_EVENT_STA_GOT_IP` case: add
  `esp_netif_sntp_start()` (idempotent/safe to call again on reconnect;
  ESP-IDF's SNTP module handles being told to start while already running).
  Non-blocking — no `esp_netif_sntp_sync_wait(...)` call, matching the
  chosen non-blocking design. Logged via the existing logger at `INFO` on
  success is not needed (the SNTP module's own event/notification is
  internal to ESP-IDF); a simple one-line `logger->info(...)` noting sync
  was (re)triggered is sufficient.

## Verification

1. `cd backend && go build ./... && go vet ./...` clean.
2. Publish a raw log-formatted string to a test node's `/pub/{device_id}/log`
   topic and confirm a `node_logs` row appears with correctly parsed
   `level`/`tag`/`message`/`logged_at`.
3. Publish a garbage (non-matching) string to the same topic and confirm a
   row still appears with `level=NONE`, `tag=''`, `message=<the garbage
   string verbatim>`, `logged_at` close to now.
4. `GET /v1/node-logs?node_device_id=...` returns the inserted rows;
   `DELETE /v1/node-logs?node_device_id=...` removes them; both require
   `node_log:get`/`node_log:remove` respectively (403 without).
5. `\d+ node_logs` in psql confirms the hypertable, compression settings,
   and the compression policy are all present
   (`timescaledb_information.compression_settings` /
   `timescaledb_information.jobs` for the policy).
6. On real hardware: flash, disconnect the device from WiFi, reconnect, and
   confirm (via serial log) SNTP resync is triggered on each reconnect
   without blocking boot; confirm a log line forwarded shortly after boot
   already carries a correct (not 1970-epoch) timestamp once SNTP has had
   a chance to sync.
